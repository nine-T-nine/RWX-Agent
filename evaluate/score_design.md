### v2

扣分后取[0,100]

### 1. 事件定义

- **时间戳**：A、B 均为指令到达游戏监听端口的游戏秒。
- **B 簇**：相邻 B 间隔 ≤ 5 s 合并，取簇首和簇尾时间。
- **A 块**：相邻两个 B 簇之间的所有 A 合成一个块，取块内第一条 A 的时间。
- **回合延迟**：
  - `Γ_BA` = B 簇尾 → 下一个 A 块首。
  - `Γ_AB` = 该 A 块首 → 下一个 B 簇首。
  - 两段之和恰好等于相邻 B 簇的间隔。在空档里塞 A 只能让延迟在两段之间转移，总量降不下来。
  - 两个 B 簇之间没有 A，则该回合不产生 f2/f3 样本。
- **空窗序列**：只使用底层命令执行记录里的命令，也就是 B 分解出来的指令，不做语义上的"有效"判断。只剔除引擎拒绝或未执行的命令。A 是查询类，不进入 f5/f6，所以靠发 A 刷不了这两项。
- **末尾空窗**：最后一条指令到结算时刻 `T_end` 的间隔计入空窗序列，它是未结束的停顿，不能丢。

### 2. 特征

参数 `lo`、`hi` 的单位是**游戏秒**。  
当 `x ≤ lo` 时 `u = 0`（满分）；当 `x ≥ hi` 时 `u = 1`（扣满该特征）。

| 特征 | 定义 | 统计量 | 计分 | 组 / 初始组权重 | lo (s) | hi (s) | 初值来源与可信度 |
|---|---|---|---|---|---|---|---|
| f1 启动 | 首条底层指令时间 h | 单值 | ✓ | 启动 / 20 | 3 | 90 | v2 原值，固定不动态。可信度高 |
| f2 | Γ_AB | 中位数 | ✓ | 回合延迟 / 40（组内与 f3 等分，各 20） | 5 | 30 | v1 A→B 断点（5 / 30）。可信度中 |
| f3 | Γ_BA | 中位数 | ✓ | 同上 | 5 | 35 | v1 B→A 断点（3–25）放宽后的 v2 值。可信度中 |
| f5 | B 簇间空窗（含末尾） | 时间加权 P90 | ✓ | 空窗 / 40（组内与 f6 等分，各 20） | 5 | 60 | v2 暂定值。统计量已改，待标定 |
| f6 | 底层指令间空窗（含末尾） | 时间加权 P90 | ✓ | 同上 | 3 | 45 | v2 暂定值。统计量已改，待标定 |
| f4 | A 块间空窗 | 时间加权 P90 | 仅诊断 | 不计分 / 0 | 5 | 60 | v2 暂定值，只用于报告，不进 S |

**时间加权 P90**：每个间隔以自身长度为权重，取累计权重达 90% 处的间隔值。含义是"随机抽一个游戏秒，它所处的空窗有多长"。批量下指令再长时间停顿，也拉得高。

### 3. 评分

```text
u_k = clip( (ln(1+x_k) − ln(1+lo_k)) / (ln(1+hi_k) − ln(1+lo_k)), 0, 1 )
g_λ(u) = (e^{λu} − 1) / (e^{λ} − 1)       # λ→0 时 g=u；λ>0 凸，宽容小延迟、严惩大延迟
S = 100 − Σ_g W_g · mean_{k∈g} g_λ(u_k)   # 三组：启动{f1} / 回合延迟{f2,f3} / 空窗{f5,f6}
```

**边界规则**

- `T_end < T_min` 不评分。
- 某特征样本数 `n < 5`：`u ← (n·u + (5−n)·1) / 5`，缺样本按停滞处理，同时输出低置信标记。
- 没有 A，f2/f3 直接 `u = 1`。
- 活跃度闸门：底层指令数 / 分钟低于 `r_min` 时，S 封顶。

### 4. 阈值 `lo/hi`

- 用**参考池**（人类对局 + 固定基线 Agent，不含待评测 Agent）标定：`lo` 取 P25，`hi` 取 P95，v1 的断点作先验。
- 只在发布新版本时重估，评测批次内冻结。去掉每批动态更新，避免慢 Agent 多了就把标尺放宽。

### 5. 验证

**扰动族**：沿用 P1–P4，新增两个对抗族。

| 族 | 操作 | 期望 |
|---|---|---|
| P1 | 整体后移 5/15/30/60 s | 仅 f1 变 |
| P2 | 间隔乘 ρ∈{1.25,1.5,2,3}，比例 20/50/100% | f2–f6 变 |
| P3 | 插入空窗 15/30/60/120 s（位置分层） | f5、f6 变 |
| P4 | 随机删 A 25/50/75% | f2/f3 样本减少 |
| P5 | 指令总数不变，重排成"大批 + 长停顿" | f5/f6 上升 |
| P6 | 在空窗里插入 A | S 不得上升 |

**优化目标**

```text
min_{W,λ}  L_pert − α·ICC(S) + β·R + μ·KL(W/100 ‖ W0/100)
L_pert = Σ log(1 + exp(−(S(m) − S(m̃)) / τ))    # S 先归一到 [0,1]
R = Σ_{i<j} ω_i ω_j |corr(u_i,u_j)| / (Σω)²     # ω_i = W_g / |g|
```

**验收**

1. 留一族交叉验证，同一局的原版与扰动版不得跨训练集和验证集。
2. 每个特征 `u ∈ {0,1}` 的对局占比 ≤ 40%。
3. 不变性：时间戳 ±1 s 抖动、同批 B 次序打乱，ΔS 在容差内。
4. 块自助：按周期重采样，报告 S 的标准差。
5. 正对照：人类对局 `u` 均值 ≤ 0.3。不满足时，先查 B 粒度是否对齐，再考虑放宽阈值。
6. 负对照：空转、成批化（P5）、塞 A（P6）都必须得低分。
7. 盲测：保留一套不公开的扰动族和对局。

### 偷袭AMBUSH
上限：35

采用逐事件累计、全局封顶的方式，并通过死区和凸函数使少数重大偷袭事件主导扣分。
每次事件扣分为 \(P_i=SingleMax\times S_i\times R_i\)，最终扣分为 \(\min(T,\sum P_i)\)，即单次事件最高扣 SingleMax 分，两次灾难性偷袭即可扣满。

- 其中，\(I_i\) 为事件期间受害单位及建筑的加权实际 HP 损失之和，即 \(I_i=\sum_j w_j\cdot\Delta HP_j/HP_{j,\max}\)，\(\Delta HP_j\) 为目标 \(j\) 在本次事件中新增的实际 HP 损失，\(HP_{j,\max}\) 为该目标自身的最大 HP，因此各目标的损失比例先按各自血量归一化，再乘以目标权重后求和，总和不要求为 1。目标权重按单位类别或最大 HP 预先确定，不随当前剩余 HP 变化：血量低/中/高单位权重分别为 1/2/3，血量低/高建筑权重分别为 2/4。
- **严重程度** \(S_i=\left(\min\left(1,\max\left(0,\dfrac{I_i-I_0}{I_{full}-I_0}\right)\right)\right)^{\gamma}\)，\(I_i\le 1\) 视为观战者难以察觉的轻微骚扰，不扣分；\(I_i\ge 12\)（约相当于损失 4 个高血量单位）时严重程度达到上限；指数 \(\gamma\) 使重大事件的扣分增长快于轻微事件，避免大量小事件的累计淹没少数最刺眼的偷袭。
- **响应系数** \(R_i=\min(1,d_i/T)\)，其中 \(d_i\) 为偷袭事件确认后至 Agent 首次有效主动响应的时间间隔（秒），T 秒及以上记为 1；若事件结束前始终没有有效响应，则按 T 秒计算。

上述 \(I_0\)、\(I_{full}\)、\(\gamma\)、单次上限 SingleMax 及事件合并间隔均为初始参数，后续根据完整对局日志中事件加权损失的分布（\(I_0\) 取 P50～P70，\(I_{full}\) 取 P95～P99）及人工回放复核进行校准。

超参数：T=35，SingleMax=18 I_0=1 I_{full}=12 gamma=3

## 第三阶段
扣分最小取0
### 1. 偷袭延迟严重程度
#### 材料收集
- 对局时长尽量在15min-30min之间，并且最好是win对局,否则就是一直被动挨打。
材料：统计全场中，只要单位处于idle状态（运输状态不算，建造者、海上建造者、战斗工程师、机械工程师处于维修、建造状态也属于idle），就统计其遭受的伤害。每个移动单位维护一个缓冲（首次idle状态遭受攻击时创建，时间也从这里开始计时T)，遭受伤害就累加伤害值、被攻击次数，（有护盾就单独统计），直到下一次行动或者死亡时，如果T>T0,那么就记录一条信息。
#### 扣分公式
后处理时，每条信息处理后得到总承受伤害值、承受伤害值/次、时长、单位类型/id

扣分公式需要注意，承受次数多少反应Agent实际收到的信息警告的频率、承受伤害值和未遂承受伤害值则间接体现Agent的反应能力（反应越快，损失越少），对局时长越长越容易发生偷袭事件因此我尽量稳定对局时长在一个范围内。那么设计合理的扣分公式
逐条记录用字段 D_hp、D_sh、N、T、HP_max、Shield_max、cost、G 、died计分：
- 如果存在升级、增益等使**上限**变化，HP_max取缓冲创建时刻的实例上限
- cost取累计造价（例如一路升级升上来的价格）

- E = D_hp + α·D_sh；H = HP_max + α·Shield_max
- 致死（died=true）：L = 1.0；否则 L = β·min(1, E/H)
- W = W_min + (1 − W_min)·min(1, ln N / ln N_sat)
- Tf = 1 + γ·min(1, (T − T0)/T_span)
- w = clip(sqrt(cost/C_w), w_lo, w_hi)
- s = w·L·W·Tf

汇总：S = Σs / clip(G/G_ref, r_lo, r_hi)；扣分 = P_max·(1 − exp(−S/S0))。另输出致死占比与 N 分布两个诊断指标（不计分）。

**可调参数及效果：**

| 参数 | 当前初值 | 效果 |
|---|---|---|
| α | 0.4 | 护盾伤害折算成血量伤害的权重；越大护盾损失越被看重 |
| β | 0.9 | 未致死记录损失上限；越大未死也越接近满损失 |
| W_min | 0.1 | 警告项下限；越大"一击秒杀"也扣得越多 |
| N_sat | 8 | 警告饱和点；越小少量受击就接近满警告项 |
| γ | 0.5 | 时长项最大加成；越大 idle 时长影响越强 |
| T0 | 3 | 时长免罚阈值（秒）；越大短时受击越免责 |
| T_span | 27 | 时长项从 1 爬到 1+γ 所需秒数；越小时长影响爬升越快 |
| C_w | 1000 | 价值权重基准造价；越大同样造价权重越小 |
| w_lo / w_hi | 0.4 / sqrt(7) | 价值权重夹逼上下限；控制贵贱单位分差 |
| G_ref | 20min | 时长归一化基准；越大长局被压得越狠 |
| r_lo / r_hi | 0.5 / 2 | 时长缩放夹逼范围；控制极端对局的影响 |
| P_max | 50 | 最终扣分天花板 |
| S0 | 基线 S 中位数，初始为1 | 饱和速度；越小越快逼近 P_max |

系数均为初值，待基线数据按 s 分布再调。

### 2. 偷家延迟严重程度（仅建筑）

#### 材料收集

- **每个建筑维护一个缓冲区**，首次遭受炮兵单位（暴力枚举，这里指定自行火炮、重型火炮、火炮机甲）攻击时创建，记录 \(t_1\)，累加 \(D_{hp}\)、\(D_{sh}\)、\(N\)。
- 创建后**任意炮兵单位**对该建筑的第二次命中记为 \(t_2\)，不要求同一攻击者。
- 每次炮击刷新超时计时；超过 \(K_{tol}\) 未再被炮击则到期，\(K_{tol}=1.3\times K\)，\(K\) 取多种炮兵中最大的平均攻击间隔。
- 缓冲区在**建筑被摧毁或到期**时关闭，建筑升级、在建造状态、回收状态、治疗状态不关闭，视为idle；**满足 \(N \ge 2\)（\(t_2\) 存在）或建筑被摧毁**才落记录。
- 记录字段：建筑类型/id、\(D_{hp}\)、\(D_{sh}\)、\(N\)、\(t_1\)、\(t_2\)、结束时刻、结束原因（摧毁/到期）。
- 建造中的建筑照常统计，\(H\) 取缓冲创建时刻的 \(HP_{max}\)。
- 如果存在升级、增益等使上限变化，HP_max取缓冲创建时刻的实例上限
- cost取累计造价（例如一路升级升上来的价格）
#### 扣分公式

E = D_hp + α·D_sh
H = HP_max + α·Shield_max

L = 1.0                         若摧毁
L = β·min(1, E/H)               否则

W = W_min + (1 − W_min)·min(1, ln N / ln N_sat)

w = clip(sqrt(cost/C_w), w_lo, w_hi)

s = w·L·W

汇总：

S = Σs / clip(G/G_ref, r_lo, r_hi)
扣分 = P_max·(1 − exp(−S/S0))

另输出摧毁占比、N 分布、各建筑类型记录数（不计分）。

#### 参数

| 参数 | 初值 | 说明 |
|---|---|---|
| α | 0.4 | 同 1 |
| β| 0.9 | 同 1 |
| W_min | 0.1 | 同 1 |
| N_sat | 4 | 炮兵射速慢，\(N\) 天然偏小 |
| C_w | 1000 | 同 1 |
| w_lo / w_hi | 0.5 / sqrt(8) | 建筑造价高，上限放宽 |
| K_tol | 1.3*K | 缓冲区超时阈值 |
| G_ref | 20min | 时长归一化基准；越大长局被压得越狠 |
| r_lo / r_hi | 0.5 / 2 | 时长缩放夹逼范围；控制极端对局的影响 |
| P_max | 50 | 最终扣分天花板 |
| S0 | 单独标定 | 用基线 Agent 在同一规则下取 S 的中位数 |
| K | 游戏数据读取，然后取最大的平均攻击间隔 | 指定攻击者集合/炮兵单位的最大的平均攻击间隔 |

#### 参数预估指南

##### 一档：用游戏数据或经验直接定

| 参数 | 估算方法 | 参考取值 |
|---|---|---|
| **K（2）** | 游戏内直接读取各炮兵单位的攻击间隔 | 读取值 |
| **N_sat（1、2）** | 先定一个"合理反应窗口"（你觉得一个合格的 Agent 该在几秒内有所反应），再用 **窗口 ÷ 攻击间隔 × 同时开火的单位数**。到这个次数还没反应，就算"警告已经满了" | 1：先看常见攻击者的间隔再算，8 只是占位值；2：对建筑，窗口 8~10s 配合炮兵间隔，通常 4~6 |
| **C_w、w_lo/w_hi** | 列出所有单位（1）、所有建筑（2）的造价。C_w 取常见单位的中位造价，使典型单位 w≈1。再算最便宜和最贵的 sqrt(cost/C_w)，把上下限定在能覆盖大部分、同时压住极端值的位置 | 1：0.5/2；2：0.5/3，需按建筑造价表核对 |
| **G_ref、r_lo/r_hi** | G_ref 取你实际对局时长的中位数。r_lo、r_hi 要覆盖 15min 和 30min 对应的比值，保证正常对局不被夹逼。G_ref=20min 时是 0.75~1.5，r_lo=0.7、r_hi=1.5 刚好覆盖 | 按你实际稳定下来的时长改 |
| **T0（1）** | Agent 的决策周期加一次人类级反应时间，约 1~2s | 3s 即可，也是记录门槛 |
| **T_span（1）** | 问自己：被打多少秒还没动，就算彻底失职？T0 到这个时长之间是爬升段 | 20~30s，27 合理 |

##### 二档：价值判断，凭经验给范围

每个参数我附了一个自问的问题，答案直接对应取值。

| 参数 | 自问 | 取值 |
|---|---|---|
| **α** | 护盾多久能回满？一点护盾值多少点血？回得快就偏低，回得慢或要技能才能回就偏高 | 0.2~0.3 / 0.5~0.7 |
| **β** | 被打到只剩一丝血没死，是否几乎等同于死了？是就取高 | 0.8~0.95 |
| **W_min** | 一击秒杀，Agent 完全没责任吗？完全没有就取小 | 0.05~0.15 |
| **γ** | 因为 T 里含有受击前的空闲，噪声较大，不宜给太大权重 | 0.3~0.5，不建议超过 0.5 |
| **P_max** | 由整个评分体系里这一项占多少分决定，不由经验决定 | 看总分设计 |

##### 三档：只能靠基线数据

**S0**：只能跑基线 Agent 后取 S 的中位数。如果想先有个占位值，可以按"一局里一个中等水平的 Agent 大概会有几次明显的偷袭、每次 s 约 0.5~1"估算，比如 3~5 次对应 S0 在 2~4 之间。这样至少不会让初始扣分饱和到 P_max，但一旦有基线数据就要替换。

##### 跑基线时重点检查

1. 看 1 的 N 分布，如果大多数记录的 N 远小于 N_sat，说明 N_sat 取高了。
2. 看 2 的 N 分布，如果建筑记录的 N 普遍已经饱和，说明 N_sat 取低了。
3. 看各单位类型的 s 占比，如果少数单位类型（比如某种造价很高的单位）占了大部分总分，就回头调 w_hi。


### 3. 信息过期延迟严重程度（绞肉机v2版本）

判定逻辑：危险区已经存在，Agent 仍让建造类单位死在其中，视为信息过期。v2 与 v1 完全独立，不去重，不使用指令信息。"我方全算"的造价比例是排除我方势力范围内死亡的唯一手段。

#### 材料收集

**1. 危险区**

- 每个区记录：圆心 c、半径 X（沿用 v1 的计算）、t_birth、状态（active/cleared）、连续不满足计数 fail。
- 范围内造价统计，以 c 为圆心、X 为半径：
  - E：敌方造价和。包含能攻击陆地单位的单位（排除建造单位、拦截机、运输单位）和对地炮塔（排除防空炮塔）。
  - F：我方造价和（指令中心算99999，我方建筑全部xR计算，升级建筑是累计cost，资源提取器视为0）。包含范围内全部存活单位和建筑，加上近 T_dead内在范围内死亡的我方单位和建筑（这里的建筑造价不算R倍率，并且资源提取器专门*R2.）（含本帧）。
  - ratio = E / (E + F)
- **触发**：我方建筑被伤害摧毁，或我方单位被伤害击杀，且该单位由陆军工厂、机甲工厂、实验工厂生产、造价 ≥ 700。回收不触发。
- **刷新**：触发点落在任一 active 区内，只把该区的 fail 清零，不新建区，t_birth 不变。
- **建立**：触发点不在任何 active 区内，按帧内聚类（见工程细节）得到圆心，满足 ratio ≥ U_create 且 E ≥ E_min 才建区。
- **检查**：每 K_z 秒对每个 active 区重算一次。ratio ≥ U_keep 且 E ≥ 0.5·E_min 则 fail 清零，否则 fail 加 1。fail ≥ N_clear 则关闭，记录 t_clear。
- **覆盖**：位置落在任一 active 区内即"在危险区内"。同时被多个区覆盖时，取其中最早的 t_birth。

**2. 建造者死亡记录**

- 对象与权重：建造者 1、海上建造者 1、战斗工程师 10、机械工程师 10。
- 记录条件，需全部满足：
  - 被伤害击杀。回收不算，随运输载具一起死亡不算。
  - 死亡时位置在 active 区内。
  - age = t_death − t_birth − Δ0 > 0。
- 记录字段：单位 id、类型、权重、t_death、死亡位置、覆盖区 id、有效 t_birth。

#### 扣分公式

- 事件聚合：同一有效区内，以第一个死亡为锚点，T_merge 内死亡的建造者合并为一个事件，视为一次决策失误。
- Σw = 事件内各建造者权重之和；t_first = 事件内第一个死亡时刻
- B = min(1, Σw / W_full)
- age = t_first − t_birth − Δ0
- L = L_min + (1 − L_min)·min(1, age / T_stale)
- P_i = SingleMax·L·B

汇总：扣分 = min(Cap, ΣP_i)。不做对局时长归一，Cap 已经封顶。另输出诊断指标（不计分）：建造者死亡漏斗、事件数、各建造者类型的事件占比。

**可调参数及效果：**

| 参数 | 当前初值 | 效果 |
|---|---|---|
| X | 沿用 v1 | 危险区半径；越大越容易覆盖到建造者，也越容易误建区 |
| K_z | 4s | 区检查周期；越小清除越及时，抖动风险越大 |
| R | 2 | 我方建筑造价计算倍率，用来加强我方势力区的判定 |
| R2 | 0.5 | T_dead我方特定建筑造价计算缩小的倍率，用来减轻野生建筑建区的门槛|
| T_dead | 5s | 近期死亡我方单位计入 F 的窗口；越大越不容易在被集火时建区 |
| U_create | 0.7 | 建区的敌方造价占比；越大越难建区 |
| U_keep | 0.4 | 保留阈值，低于 U_create 形成滞回；越小区越不容易被清除 |
| E_min | 1500 | 建区所需敌方最小造价；防止侦察兵击杀一座建筑就建区，按造价表校准 |
| N_clear | 2 | 连续不满足几次才清除；越大区越稳定，但越晚关闭 |
| 触发单位造价门槛 | 700 | 中级以上单位的定义，建筑一律触发 |
| Δ0 | 5s | 建区后的信息宽限；越大越免责 |
| T_merge | 5s | 事件聚合窗口；越大同一批死亡越容易合并 |
| T_stale | 30s | L 从 L_min 爬到 1 所需的秒数；越小越快接近满扣分 |
| L_min | 0.4 | 刚过宽限期的基础严重度 |
| W_full | 10 | 规模项饱和权重；一个战斗工程师即可达到 |
| SingleMax | 4 | 单次事件最高扣分 |
| Cap | 20 | 本项扣分上限 |

系数均为初值，待基线数据按漏斗和事件分布再调。
#### 参数预估

##### 一档：用游戏数据直接算

| 参数 | 估算方法 |
|---|---|
| **X** | 沿用 v1，不用另估 |
| **E_min** | 看造价表：想让"最少多少敌人才算危险"落在哪一档。你定的 1500 约等于 2~4 个 T1/T2 战斗单位（350~700 一个），能排除单个侦察兵或单个炮塔，合理。检验方法是看建区时 E 的分布，E 紧贴 1500 的区占多数，说明门槛在起筛选作用 |
| **触发单位造价门槛 700** | 直接列出陆军工厂、机甲工厂、实验工厂的产出单位造价，700 以上的是哪些，是否符合你对"中级以上"的认知，按分档定即可 |
| **W_full** | 等于一个战斗工程师的权重 10，由权重比决定，不用估 |
| **T_dead** | 等于"一场小规模交战里，我方单位从开始被集火到死光的时长"，取 3s 是经验值，看录像里一波集火的持续时间就能校准 |

##### 二档：靠游戏经验判断

| 参数 | 自问的问题 | 取值参考 |
|---|---|---|
| **Δ0** | Agent 从"观测到死亡"到"能下令撤回"最短要多久？先看你 Agent 的决策周期 | 决策周期 + 1~2s，4s 合理 |
| **K_z** | 一场交战的节奏有多快？检查太快会抖，太慢会让失效的区挂得太久 | 你改成 4s，配合 N_clear=3，意味着区最短要 12s 不满足才清除，比之前的 6s 更稳，但滞后更久。**这是需要注意的权衡**：区在交战结束后可能多挂 12s，期间进入的建造者死亡会被误计。如果观察到这类误判，把 N_clear 降到 2 |
| **N_clear** | 同上，与 K_z 联动 | 清除延迟 ≈ K_z × N_clear |
| **T_merge** | 一次"决策失误"通常持续多久？同一条指令派出的一批建造者，死亡时间相差多少 | 3~5s，看录像里成批送死的间隔 |
| **T_stale** | 区存在多久后，还往里送就是完全不可原谅？ | 20~40s，30s 合理 |
| **L_min** | 刚过 Δ0 就送，是否仍有基础责任？ | 0.2~0.4 |
| **SingleMax / Cap** | 由总分分配决定，不靠经验。40 的 Cap 对应 SingleMax=5 下约 8 次满额事件封顶，如果你希望"少数重大事件主导"，Cap 偏宽 | 看你给 v2 分配的总分 |

##### 三档：只能靠回放数据

**R、U_create、U_keep 这三个是联动的，必须一起跑**。

**R = 2.5 的含义**：我方建筑造价乘 2.5 计入 F。它的作用是让"我方基地里的区"更难建起来，也就是你想排除的"我方势力范围内死亡"。要注意它带来两个副作用：

1. 基地里建筑密集时，ratio 会被压得很低，基本建不出区。这是你想要的，但也意味着**基地被敌人打进来时，v2 基本不会触发**。如果这种场景也是你想覆盖的，R 就不能太大。
2. R 与 U_create=0.7 叠加后很严格：F 里每 1000 造价的建筑，等效要敌方多出 2.3×1000/…，具体说就是 ratio ≥ 0.7 要求 E ≥ 2.33×F。F 里有一栋 2000 造价的建筑，等效 5000，敌人要有约 11700 造价才能建区。

校准方法：

| 步骤 | 做什么 |
|---|---|
| 1 | 回放里人工挑 20~30 个"建造者明显白送"的场景，记录当时的 E 和 F（建筑和单位分开） |
| 2 | 算这些场景的 ratio 分布，看有多少能超过 U_create |
| 3 | 再挑 20 个"建造者在我方势力范围内死亡"的场景，看有多少被 R 和 U 压住了 |
| 4 | 在两组之间找最能分开的 (R, U_create) 组合 |

**U_keep** 取 U_create 的 55%~60% 通常够用，0.4 对 0.7 约 57%，是合适的。

##### 漏斗诊断里重点看的指标

| 指标 | 说明的问题 |
|---|---|
| 建区总数偏少，触发后被丢弃的聚类占大多数 | U_create、R 偏严，E_min 偏大 |
| 区的平均存活时长远超交战时长 | K_z × N_clear 偏大，或 U_keep 偏小 |
| 同一位置 10s 内关闭又重建 | 抖动，U_keep 与 U_create 差距不够，或 N_clear 偏小 |
| 漏斗末端（计分）接近 0 | 先放宽 U_create、R，再看 Δ0 |

#### 工程细节：信息过期延迟 v2

##### 1. 每帧处理顺序

同一帧内的所有死亡先收集，再统一处理，保证结果与扫描顺序无关。

| 步骤 | 内容 |
|---|---|
| 0 | 把本帧死亡的我方单位和建筑写入 3s 死亡台账（带位置、造价、时刻）。过期条目移除 |
| 1 | 扫描本帧死亡，分类为触发列表和建造者列表，回收和运输内死亡直接丢弃 |
| 2 | 触发点落在已有 active 区内的，刷新该区（fail 清零） |
| 3 | 若本帧落在 K_z 节拍上，检查所有 active 区，更新 fail，必要时关闭。本帧新建的区不参与 |
| 4 | 剩余触发点聚类建区 |
| 5 | 用步骤 4 之后的区集合判定建造者死亡 |

刷新放在检查之前，是为了让"本帧刚发生的我方死亡"能阻止区被清除。

##### 2. 帧内聚类

1. 剩余触发点按单位 id 升序排序，保证结果确定。
2. 取列表第一个触发点作为圆心，吞掉与它距离 ≤ X 的所有触发点。
3. 对该圆心计算 ratio 和 E，满足 U_create 和 E_min 则建区，不满足则丢弃这个圆。
4. 对剩余点重复，直到列表清空。

被吞掉的触发点不会再单独建区。如果圆建不起来（ratio 不够），被吞掉的点也一并丢弃，不再单独尝试。

##### 3. 造价统计的实现

- 使用游戏真值，不受视野限制，衡量的是"客观上已经危险"。
- 用网格哈希做范围查询，每次 ratio 计算只遍历圆内格子。
- 3s 台账用环形缓冲存储，每条记录有位置、造价、时刻，范围查询时加入 F。
- 敌方静态表需要给每个单位类型打标记：能否攻击陆地、是否建造单位、是否拦截机、是否运输单位。炮塔类型打标记：对地或防空。
- 造价取单位或建筑的基础造价，不含升级。

##### 4. 区的状态机

- **active → cleared**：连续 N_clear 次检查不满足 U_keep 或 0.5·E_min。关闭后保留记录，供后处理使用。
- **滞回**：建区用 U_create，保留用 U_keep，两者之间的区间不清除，避免在阈值附近反复开关。
- **刷新**：区内新发生触发死亡，fail 清零。交战持续时区不会被清除。
- **圆心固定**：不随敌人移动，也不重新计算质心，避免区漂移。
- **关闭后的敌人回来**：必须再发生一次触发死亡才重新建区，新区 t_birth 重新计时。

##### 5. 区的重叠

- 不合并区，用圆的并集：位置落在任一 active 圆内即在危险中。
- 前线推进会产生一串圆，各自独立检查、独立清除，不会无限增长。
- 被多个圆覆盖的点取最早 t_birth，保证 age 不被后建的圆压小。
- 触发点落在任一 active 区内只刷新，不新建，防止同一场战斗不断生成新圆。

##### 6. 建造者死亡的判定细节

- 判定用步骤 4 之后的区集合。与区同帧建立的死亡，age = −Δ0 < 0，不会被记录。
- 建筑被打爆的同帧，建造者死亡也被 Δ0 排除，不需要额外规则。
- 事件时间取第一个死亡的 t_death。这样一批死亡里，第一个建造者的 age 决定 L，对 Agent 更宽松。
- 聚合以第一个死亡为锚点，不做链式扩展，避免长串死亡无限合并。
- 同一建造者只产生一条记录。

##### 7. 记录与离线调参

区的建立和清除依赖 X、U、E_min、K_z、N_clear，改动这些参数要重跑对局。下面这些参数只用于计分，记录里已有足够信息，可以离线调整：Δ0、T_stale、L_min、T_merge、W_full、SingleMax、Cap。

所以建造者死亡记录需要包含 t_death、覆盖区 id、该区的 t_birth，区日志需要包含 id、c、X、t_birth、t_clear。

##### 8. 验证与诊断

漏斗诊断，每一级的掉量对应一个参数：

建造者总死亡 → 被伤害击杀 → 非运输 → 死亡时在 active 区内 → age > 0 → 计分

区的质量指标，不计分：

- 区总数、平均存活时长、触发后被丢弃的聚类数。
- 抖动率：同一位置附近 10s 内关闭后又重建的区数量。
- 基地范围内的建区情况：我方建筑造价很高，敌人打进基地时 ratio 可能长期低于 U_create，需要观察基地内的建造者死亡是否几乎都漏判。

人工验证：回放中人工标注约 30 次建造者死亡，分为"明显白送"、"不是"、"说不清"，对比公式的命中情况。

##### 9. 已知局限

1. 基地内的我方建筑会拉低 ratio，基地区域可能建不起区。如果漏斗显示基地内几乎不计分，再考虑给非炮塔建筑的造价乘折扣。
2. 区必须有一次触发死亡才能建立，建造者是第一个死的（没有先损失建筑或中级以上单位）则不计分。这是宁漏勿错的代价。
3. K_z 检查有最多 K_z 秒的滞后，区实际已失效但尚未被清除时，建造者死亡可能被误计。2s 的周期下影响很小。
4. 区只衡量客观危险，不衡量 Agent 是否看到了危险，Δ0 是对这一点的唯一补偿。

### 4. 资金空余v2

上限 SingleMax 分。

**预处理与区间划分。** 对每秒资金做 3 秒中值平滑。设阈值 $\theta(t)=K\times$ 近 30 秒平均收入率.资金首次达到 $\theta$ 时开始计时，累计囤积时长记为 $D$。

**花费判定。** 一次花费指资金连续下降直至回升前的总降幅 $s$，$M$ 为当前区间内资金最大值。仅当 $s>\max(800,\,25\%M)$ 时计入，较小花费忽略。计入的花费按 $s/M$ 分三档折减 $D$：

| 档位 | 条件 | 处理 |
|------|------|------|
| 一 | $s/M\le 50\%$ | $D\leftarrow\rho_1 D$，$\rho_1=0.5$ |
| 二 | $50\%<s/M\le 80\%$ | $D\leftarrow\rho_2 D$，$\rho_2=0.25$ |
| 三 | $s/M>80\%$ | 视为彻底释放，区间结束，$D$ 清零重计 |

资金回落到 $\theta$ 以下时，区间同样结束。

**区间结算。** 每区间时长 $d_k$ 取区间内 $D$ 达到过的最大值（已累计囤积不因后续部分释放被抹去）。

最终扣分$$F=\min\Big(SingleMax,\ \sum_k 7\,f(d_k)\Big)$$
f(d_k):(15,120)平移指数 `y=e^(x-a)+b` {0,1}(120,?)封顶{1}

参数K=30

**参数校准。** $K$、$d_0$、$d_1$ 与最小花费阈值由同分层参考对局动态估计（剔除本局），
并向先验（$K=30,\ d_0=15,\ d_1=120$）收缩后裁剪：

- $K=\operatorname{clip}\big(\operatorname{median}_m Q_{0.9}(r_m),\,20,\,45\big)$，$r_m(t)=$ 资金 / 近30秒收入率
- 用该 $K$ 重算参考池区间，$d_0=Q_{0.5}(d_k)$，$d_1=Q_{0.95}(d_k)$，分别裁剪至 $[8,25]$、$[90,180]$
- 最小花费：$s>\max(\kappa\cdot\text{收入率},\,25\%M)$
- $f(d)=\dfrac{e^{\lambda u}-1}{e^{\lambda}-1}$，$u=\dfrac{d-d_0}{d_1-d_0}$，$d\ge d_1$ 时封顶为 1
- 参考池区间数不足 30 时退回先验；每个评测批次冻结参数快照
- SingleMax=30
