# task-017：命令记录文件按地图命名

- 目标：`evaluate/output` 下的命令记录名过长且难识别，改为 `commands-<地图名>-<日期>--<唯一编号>.txt`，统计文件同名 `-stats.txt`；尾部随机编号沿用原规则。
- 改动：
  - `CommandRecorder` 启动时命名为 `commands-lobby-<yyyyMMdd>--<id>.txt`（`id` 仍取 `Files.createTempFile` 的随机数），首个有效对局在 `enterMatch` 中把命令与统计两份文件改名并重新打开，随机编号保持不变；改名后补打一行 `RWX_CLI_COMMAND_RECORDING`。
  - 地图名经 `mapSlug` 归一：空白与 Windows 非法字符（`<>:"/\|?*`）压成单个 `-`，去掉尾部点/横线，限长 48；空地图名不消耗改名机会，下一局仍会命名。改名失败保留大厅文件名并告警。
  - 同一进程只命名一次：后续对局沿用首局地图名，各局地图与进入时间继续记在统计首部。
- 验证：`RwxCliCommandCaptureTest` 新增 2 项（改名规则、编号保持、旧文件消失、大厅命令保留、后续对局不改名；地图名清洗与无地图回退），并补引擎单例初始化使该测试类可单独运行；完整 `:core:test` 26 套件、226 项、零失败。
- 遗留：同一进程内多局共用首局地图名；若需要每局独立文件，需另定轮转规则。
