# 尺寸与距离单位（RWX / Rusted Warfare）

三类"尺寸"在代码里各有一套单位，混用会差 20 倍。写 AI、改 ini、算覆盖范围前先看这一页。

```
1 格 (tile) = 20 世界单位 (world unit) = 20 像素 (zoom = 1)
tileWorldSizeX/Y = 20        tileScaleX/Y = 1/20 = 0.05        halfTileWorldSize = 10
地图世界尺寸 = tileCountX/Y × 20        （.tmx 的 width/height 就是格）
```
证据：`TileMap.java:715-724`（默认 20；space 模式 60 见 `:717-719`，但本仓库 `spaceGameMode` 只有声明/读取、无赋值点 → 实测恒为 false）、`:1369-1376`、`:621-686`；`GameLogic.java:2064-2066`（`visibleWorldWidth = 屏幕像素 / zoom` → zoom=1 时 1 世界单位 = 1 像素）。

## 1. 哪些量是"格"，哪些是"世界单位"

| 单位 = 格（整数，直接加到 tile 索引上） | 单位 = 世界单位（float，参与距离运算） |
|---|---|
| `footprint` / `constructionFootprint` / `displayFootprint`（`IniFile.getRect` 强制 4 个 int） | `radius` / `displayRadius`（解析时 ×`globalScale`） |
| `fogOfWarSightRange`（默认 15；在 tile 空间比较距离） | `maxAttackRange`（炮台 `m()`）、`nanoRange`（修复湾 `y()` = 230） |
| `AiMapGraph` 的区域 / BFS 距离场、前线 band 与深度 | 所有 `posX/posY`、速度、`BaseZone.radius = 420`（21 格） |

- 解析：`CustomUnitConfigParser.java:1705-1710`（footprint）、`:1696-1712`（radius ×globalScale）、`:2033-2039`（maxAttackRange）、`:1752-1772`（nanoRange）。
- ⚠️ 陷阱：`buildingToFootprintOffsetX/Y` 是 **float 但语义是世界单位**（默认 10 = 半格，`CustomUnitConfigParser.java:1709-1710`）。
- ⚠️ 唯一反例：抛射物 `areaRadius`（溅射半径）是世界单位、**不乘 globalScale**（`CustomProjectileTemplate.java:50-53`；对比 `CustomUnitConfigParser.java:2078-2085`）。
- ini 里所有长度量（radius / attackRange / nanoRange / moveSpeed…）都乘 `globalScale`；footprint 系列不乘。

## 4. 贴图：默认 1 像素 = 1 世界单位

- 尺寸来源：贴图是**水平多帧动画条**；`frameWidth = 贴图宽 / total_frames`（ini，`CustomUnitConfigParser.java:1351-1352`）或构造器字面量（Java：`SizedObject.java:20-24`，如 `HeavyTankUnit.java:95` = 3 帧）。
- 绘制 = 帧像素 × `imageScale`（默认 1.0）；`getRenderScale()` 恒 1.0。`scaleImagesTo : N` 表示"整图绘成 N 世界单位宽"，**只改绘制**，radius/footprint 不变（`CustomUnitConfigParser.java:1410-1425`）。全仓库 53 处 `#scaleImagesTo: 20` **全是注释**，即实际都用 1:1。
- Java 内置建筑贴图在 `assets/drawable/*.png`（`R.drawable.*` 加载）；`land_factory.png`(50×64) **无代码引用**，实际用的是 `land_factory_front.png` / `_back.png`(50×74)。

## 5. 两个常见误判

| 目测 | 代码真实值 | 贴图真实值 | 结论 |
|---|---|---|---|
| 陆军工厂「3×4」 | 放置框 **3×5 格**（60×100）、命中框 3×3、推挤圆 r=30 | 前后两层各 50×74 px = 2.5×3.7 格 | 三者都不同；恰好 3×4 的是**空军基地**的放置框 |
| 重型坦克「1×2.5」 | 无矩形，只有 r=15 的圆（直径 1.5 格） | 车身 22×36 = 1.1×1.8 格；含炮塔 16×42 ⇒ 约 1.1×2.1 格 | 目测是贴图帧尺寸；碰撞是圆，车头/炮管会伸出圆外 |

## 6. 写 AI 时的约定

- 覆盖半径 / 攻击距离 / 纳米距离一律用**世界单位**：`AiPlacement.coverageRadius = max(m(), y())`。
- "N 格"换算：`N × 20` 世界单位（例如"炮台后方 5 格" = 100，"矿覆盖半径 200" = 10 格）。
- 区域的 BFS / 距离场 / 前线 band / 后方深度一律用**格**（`AiMapGraph`、`AiTerritory`）。
- 判断"某单位是否在建筑覆盖内"用 `countWithin(..., r)`（世界单位），不要拿 footprint 的格数当半径。
